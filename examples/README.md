# Example output

`sample-output/` is **real, committed output** of loopkit run against the
fixture project in [`../test/fixtures/sample-repo`](../test/fixtures/sample-repo)
(a small invented tool called `snapdiff`). It is regenerated by:

```bash
node bin/loopkit.js landing   --repo test/fixtures/sample-repo --out examples/sample-output
node bin/loopkit.js launch    --repo test/fixtures/sample-repo --out examples/sample-output
node bin/loopkit.js checklist --repo test/fixtures/sample-repo --out examples/sample-output
```

Look at it before you run loopkit on your own repo. Specifically notice:

- **`launch/show-hn.draft.md`** — the feature bullets and the "what it does
  NOT do" line are restated **verbatim** from snapdiff's README. The
  *personal* "why I built this" and "my ask" are loud
  `[loopkit: FILL THIS IN — …]` placeholders. loopkit did not write a
  backstory.
- **`launch/changelog-announcement.draft.md`** — built only from the real
  `1.2.0` entry in the fixture's CHANGELOG. It says "3x faster" because the
  changelog says exactly that — not "10x", not "blazing".
- **`payments/INTEGRATION.md`** — documentation and `TODO(you)` markers.
  Search it: there is no payment SDK, no key, no endpoint.
- **`index.html`** — open it in a browser. No network requests, no JS, view
  source and confirm.

Determinism: re-running the commands produces byte-identical files. That is
asserted by the test suite, and it is why these can be safely committed.
